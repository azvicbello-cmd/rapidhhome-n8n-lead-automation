Architecture

One clear path from enquiry to action.

The core is intentionally reusable: intake and security first, deterministic processing in the middle, then client-specific routing and downstream actions.

Sanitized architecture view. Credentials, tokens and private identifiers are excluded from the public project.
Receive→ Verify→ Normalize→ Score→ Deduplicate→ Store→ Route→ Notify
How it works

Built around predictable business logic.

01

Authenticated intake

Accepts POST requests through a protected webhook rather than exposing an unrestricted endpoint.

02

Request integrity

HMAC-SHA256 verification checks that the received payload matches the payload that was signed.

03

Normalization

Incoming lead fields are transformed into one consistent internal structure before business rules run.

04

Deterministic scoring

Contact completeness and urgency signals produce a transparent HOT, WARM or COLD classification.

05

Duplicate protection

A deterministic lead key is checked against persistent storage to prevent repeat processing.

06

Persist before notify

New leads are stored before downstream notification, reducing the risk of losing a lead if an alert fails.

07

Priority routing

HOT leads move immediately to the urgent path while WARM and COLD paths remain available for different follow-up strategies.

08

Explicit outcomes

The caller receives structured responses for success, duplicates, invalid signatures and notification failures.

Reliability

Designed beyond the happy path.

The workflow treats external services and repeated requests as real failure scenarios rather than assuming every execution succeeds once.

✓
Two request checksHeader authentication controls access, while HMAC validation checks payload integrity.
↻
Idempotent processingRepeated deliveries are recognized so the same event does not create uncontrolled duplicate records or alerts.
!
Notification failure handlingTelegram delivery can retry, then move to a dedicated failure path rather than silently reporting success.
↗
Reusable coreScoring, thresholds, source systems, notification channels and downstream integrations can be changed per client.
